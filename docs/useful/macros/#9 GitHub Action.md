#### GitHub Pages подготовка статичных страниц

Выполнить публикацию вручную:

1. Открыть CMD;
2. Зайти в папку с проектом, используя команду ```cd```;
3. Убедится, что находитесь в ветке main и что все изменения собраны в коммиты и залиты в ```main```;
4. Выполните команду для сборки и публикации сайта:

```shell
mkdocs gh-deploy
```

Если процесс прошёл без ошибок, в ответе на команду ```mkdocs gh-deploy``` отобразится URL сайта:

```
<…>
To https://github.com/novillero/parawriter_docs.git
 * [new branch]      gh-pages -> gh-pages
INFO    -  Your documentation should shortly be available at: https://novillero.github.io/parawriter_docs/
```

1. Открыть репозиторий в *Github* и перейти на вкладку *Settings*;
2. В левом меню выберите пункт *Pages*;
3. На этой странице указаны настройки публикации сайта на *GitHub Pages*.

Проверить на установленные значения:
>Sourse — Deploy from a branch;
>Branch — gh-pages; folder — /(root).

Это значит, что сайт публикуется из ветки, ветка для публикации — gh-pages.

1. Открыть вкладку Action. Здесь отображаются все запущенные *workflow* публикации сайта.

>Каждый раз, когда вы запускаете сборку командой mkdocs gh-deploy, в разделе Actions → All workflow появляется новая запись.

1. Нажать на запись, чтобы увидеть подробности сборки и ссылку на опубликованный сайт. Зелёная галочка сообщает о том, что процесс прошёл удачно и сайт опубликован. **Красный крестик показывает, что сборка и публикация завершились ошибкой. В этом случае стоит проверить валидность конфига и файлов проекта.**

Ошибки и предупреждения можно посмотреть с помощью команды ```mkdocs serve``` — все они отобразятся в командной строке.

>Главная цель достигнута — сайт с документацией опубликован. Теперь вы можете каждый раз после обновления проекта (вливания рабочей ветки в main) запускать пересборку и публикацию изменений.
