## Senior: «Определяю стандарт и проектирую архитектуру»

На Senior-уровне SSG становится **элементом архитектуры документации**. Вы не просто настраиваете генератор для одного проекта, вы **определяете стандарт для организации**, проектируете масштабируемую архитектуру и управляете lifecycle документационных сайтов.

**Что входит в Senior-уровень:**

- **Стратегия SSG для организации:** вы определяете, какой SSG используется в компании (или какие для разных продуктов), как он связан с другими инструментами: OpenAPI, CI/CD, системами аналитики.
- **Архитектура документации:** вы проектируете модульную архитектуру: как связаны разные документационные сайты, как работает кросс-продуктовая навигация, как обеспечивается единый поиск.
- **Governance:** вы определяете политику: кто отвечает за обновление SSG, как обрабатываются breaking changes, как проверяется качество сборки.
- **Масштабирование:** вы проектируете систему, которая выдерживает рост: добавление новых продуктов, языков, версий без полной перестройки.
- **Автоматизация:** вы настраиваете пайплайн: контент → lint → build → test → deploy. Вы используете CI-гейты для проверки качества.
- **Метрики:** вы измеряете эффективность документационного сайта: page views, time-to-find, search queries, adoption.
- **Обучение:** вы обучаете команды работе с SSG, проводите воркшопы, создаёте внутренние стандарты.
- **Выбор и оценка инструментов:** вы проводите сравнительную оценку SSG (MkDocs, Docusaurus, Sphinx, Hugo, Antora) и обосновываете выбор для организации.

*Ключевой принцип Senior: вы **определяете правила игры** и **отвечаете за их соблюдение в масштабе**. Документационный сайт становится частью продуктовой стратегии.*

### Курсы и книги (Senior)

[Antora Essentials: The Complete Guide for Developers and Engineers](https://www.amazon.com/Antora-Essentials-Complete-Developers-Engineers/dp/1484286547) - Для documentation architects и senior technical writers: модульная архитектура документации, стратегическое сравнение SSG, масштабирование;

[Docs-as-Code Setup Guide (GitHub, разделы о governance)](https://github.com/ann-kilzer/docs-as-code-setup-guide) - Разделы о документационной governance: placement matrix, правила размещения контента, lifecycle;

[Technical-Writing-Masterclass-A: Module 7 (TECH-OPSS)](https://github.com/TECH-OPSS/Technical-Writing-Masterclass-A) - Module 7 полностью о docs-as-code инструментах: Git, SSG, CI/CD, AI-ассистенты;

[Write the Docs: Software Documentation Guide](https://www.writethedocs.org/guide/) - Best practices для документации, включая архитектуру сайта и governance;

[Docs for Developers (Jared Bhatti et al.)](https://link.springer.com/book/10.1007/978-1-4842-7295-1) - Стратегия документации, архитектура, масштабирование, обучение команды.
