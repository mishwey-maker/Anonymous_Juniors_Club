## Middle: «Настраиваю генерацию и интегрирую в CI/CD»

На Middle-уровне автоматизация генерации перестаёт быть просто «запуском инструмента». Теперь это **предмет настройки и интеграции**: вы создаёте пайплайн, который автоматически генерирует документацию при каждом изменении кода, проверяет её качество и публикует.

**Что входит в Middle-уровень:**

- **Настройка генерации из OpenAPI:** вы настраиваете `redocly.yaml` или `swagger-config.yaml` для тонкой настройки генерации: какие эндпоинты включать, как группировать, какие примеры показывать. Вы используете `x-codeSamples` для добавления примеров на разных языках.
- **Генерация из комментариев в коде:** вы настраиваете Sphinx (Python), DocFX (.NET/Java), JSDoc (JavaScript) или Doxygen (C++). Вы понимаете, как писать docstrings, которые хорошо генерируются: параметры, возвращаемые значения, примеры.
- **AST-анализ и AI-генерация:** вы работаете с инструментами, которые используют AST-анализ для понимания структуры кода: `know-cli`, `code2docs`, `codeledger`. Вы понимаете, как AI генерирует документацию из кода и как это проверять.
- **Интеграция в CI/CD:** вы настраиваете GitHub Actions (или GitLab CI) так, чтобы генерация документации запускалась при каждом изменении кода: `on: push` → генерация → валидация → деплой. Вы используете CI-гейты: если сгенерированная документация не проходит валидацию, PR не может быть смержен.
- **Синхронизация с кодом:** вы настраиваете пайплайн так, чтобы документация всегда соответствовала актуальной версии кода. Вы используете `codeledger generate` для создания снимков документации и `codeledger merge` для объединения их в финальный документ.
- **Валидация сгенерированной документации:** вы проверяете, что сгенерированная документация корректна: все ссылки работают, примеры запускаются, схемы валидны. Вы настраиваете автоматическую проверку в CI.

*Ключевой принцип Middle: вы **настраиваете и интегрируете**. Вы отвечаете за то, чтобы генерация работала надёжно и документация всегда была актуальной.*

### Курсы и книги (Middle)

[Schulung Docs-as-Code: Technische Dokumentation mit Git, Markdown und CI/CD (GFU)](https://www.gfu.de/schulung/docs-as-code/) - 2-дневный интенсив: автоматизированные publishing-пайплайны, Static Site Generators, CI/CD, генерация документации;

[Automated Documentation Sites with Backstage TechDocs (CloudThat)](https://www.cloudthat.com/resources/blog/automated-documentation-sites-with-backstage-techdocs) - Реальный кейс: настройка автоматической генерации сайта документации из Markdown в CI/CD. Prepare → Generate → Publish;

[code2docs Documentation](https://pypi.org/project/code2docs/) - Инструмент для автоматической генерации и синхронизации документации из исходного кода. Поддерживает MkDocs, watch mode, sync markers;

[codeledger Documentation](https://pypi.org/project/codeledger/) - AI-ассистированная генерация документации: scan → parse → classify → generate → merge. Поддерживает Ollama (бесплатно);

[Docs Like Code (Anne Gentle)](https://www.oreilly.com/library/view/docs-like-code/9781492049364/) - Классика docs-as-code: collaboration, automation, test automation, continuous integration. Как выстроить систему генерации.
