## Senior: «Определяю стандарт и управляю системой генерации»

На Senior-уровне автоматизация генерации становится **элементом архитектуры документации**. Вы не просто настраиваете генерацию для одного проекта, вы **определяете стандарт для организации**: какие источники истины используются, как обрабатываются исключения, как измеряется качество сгенерированной документации.

**Что входит в Senior-уровень:**

- **Стратегия источников истины:** вы определяете, что является единым источником истины для каждого типа документации: OpenAPI для API reference, docstrings для SDK reference, код для архитектурных диаграмм. Вы понимаете, как связать разные источники.
- **Governance:** вы определяете политику: кто отвечает за актуальность спецификаций, как обрабатываются breaking changes, как проверяется, что сгенерированная документация соответствует реальности.
- **Масштабирование:** вы проектируете систему, которая выдерживает рост: добавление новых API, языков, версий без переписывания конфигураций для каждого.
- **Кросс-продуктовая генерация:** вы обеспечиваете, чтобы генерация работала across products: единый пайплайн для всех API, единый стиль сгенерированной документации.
- **Метрики качества:** вы измеряете эффективность генерации: покрытие API документацией (какой процент эндпоинтов задокументирован), свежесть документации (насколько она отстаёт от кода), количество ошибок в сгенерированной документации.
- **Обучение:** вы обучаете команды работе с генераторами, проводите воркшопы, создаёте внутренние стандарты.
- **Влияние на дизайн:** вы участвуете в design-ревью API и кода, предлагаете улучшения, которые делают генерацию более полной и точной.

*Ключевой принцип Senior: вы **определяете правила игры** и **отвечаете за их соблюдение в масштабе**. Генерация документации становится частью инженерной культуры.*

### Курсы и книги (Senior)

[Implementing Structured Authoring Practices in a Docs-as-Code Framework (ACM)](https://dl.acm.org/doi/10.1145/3641237.3691677) - Реальный кейс: структурированное авторство, генерация документации, автоматизация, масштабирование;

[Docs as Tests (Manny Silva)](https://www.docsastests.com/) - Как применять концепцию тестирования к документации: автоматическая проверка актуальности, генерация из единого источника истины;

[Technical Writing for Software Developers (Chris Chinchilla)](https://www.oreilly.com/library/view/technical-writing-for/9781098141349/) - Главы о docs-as-code, toolchains, автоматизации, генерации документации;

[Docs-as-Ecosystem (Alejandra Quetzalli)](https://docs-as-ecosystem.com/) - Community approach to engineering documentation: как выстроить экосистему документации с автоматизацией;

[Docs for Developers (Jared Bhatti et al.)](https://link.springer.com/book/10.1007/978-1-4842-7295-1) - Стратегия документации, архитектура, масштабирование, обучение команды.
