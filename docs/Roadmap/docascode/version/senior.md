## Senior: «Определяю стандарт и управляю lifecycle версий»

На Senior-уровне версионирование становится **элементом архитектуры документации**. Вы не просто настраиваете версии для одного проекта, вы **определяете стандарт для организации**, управляете lifecycle версий и обеспечиваете, чтобы документация для всех продуктов версионировалась консистентно.

**Что входит в Senior-уровень:**

- **Стратегия версионирования для организации:** вы определяете, какие продукты версионируются, по какой схеме, как долго поддерживаются старые версии. Вы понимаете, что версионирование — это не только техническая, но и **продуктовая** задача: сколько версий поддерживать, как коммуницировать end-of-life.
- **Governance:** вы определяете политику: кто отвечает за создание новой версии документации, как проверяется соответствие документации и продукта, как обрабатываются breaking changes в документации.
- **Масштабирование:** вы проектируете систему, которая выдерживает рост: добавление новых продуктов, языков, версий без переписывания конфигураций для каждого.
- **Кросс-продуктовое версионирование:** вы обеспечиваете, чтобы версии документации для разных продуктов были согласованы. Например, если продукт A и продукт B используются вместе, их документация должна версионироваться синхронно.
- **Интеграция с релизным циклом:** вы интегрируете версионирование документации с процессом релизов продукта: при создании релиза автоматически создаётся версия документации, при обновлении продукта — обновляется документация.
- **Метрики:** вы измеряете эффективность версионирования: сколько пользователей остаются на старых версиях, как часто они переключаются, снижается ли количество обращений в поддержку.
- **Обучение:** вы обучаете команды работе с версиями, проводите воркшопы, создаёте внутренние стандарты.

*Ключевой принцип Senior: вы **определяете правила игры** и **отвечаете за их соблюдение в масштабе**. Версионирование документации становится частью продуктовой стратегии.*

### Курсы и книги (Senior)

[Implementing Structured Authoring Practices in a Docs-as-Code Framework (ACM)](https://dl.acm.org/doi/10.1145/3641237.3691677) - Реальный кейс: version control, structured authoring, SSG, deployment options, content maintenance strategies;

[Docusaurus Release Process](https://docusaurus.io/community/release-process) - Пример управления версиями в крупном open-source проекте: SemVer, major/minor/patch, политика поддержки старых версий;

[Antora: Version Facets (docs.antora.org)](https://docs.antora.org/antora/latest/playbook/configure-content-sources/) - Продвинутое версионирование: actual version, prerelease, display, symbolic. Управление версиями в масштабе;

[Docs for Developers (Jared Bhatti et al.)](https://link.springer.com/book/10.1007/978-1-4842-7295-1) - Стратегия документации, архитектура, масштабирование, обучение команды;

[Write the Docs: Software Documentation Guide](https://www.writethedocs.org/guide/) - Best practices для документации, включая версионирование и governance.
