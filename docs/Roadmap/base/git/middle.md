Middle: «Настраиваю и выбираю»

На Middle-уровне Git перестаёт быть просто «инструментом, которым я пользуюсь». Теперь это предмет решений: какую стратегию ветвления выбрать для проекта документации, как настроить ревью, как автоматизировать проверки, как обеспечить консистентность между несколькими авторами.

Что входит в Middle-уровень:

* **Стратегии ветвления:** вы понимаете разницу между trunk-based workflow, GitHub flow и versioned branches. Trunk-based — все изменения в main, подходит для маленьких команд без сложного ревью. GitHub flow — каждая задача в ветке + PR, стандарт для docs-as-code. Versioned branches — для документации с версионированием.

* **Разрешение конфликтов:** вы уверенно решаете merge conflicts, понимаете, когда использовать rebase, а когда — merge.

* **Работа с PR на продвинутом уровне:** вы настраиваете шаблоны PR, ревьюеров, labels, автоматические проверки.

* **Git hooks и автоматизация:** pre-commit hooks для проверки Markdown, интеграция с линтерами (Vale, markdownlint), настройка CI для документации.

* **Ревью документации:** вы понимаете, как проводить ревью PR с документацией: что проверять, как давать фидбек, как разрешать спорные правки.

* **Метки и теги:** вы используете git tag для версий документации, понимаете, как связать версию docs с версией продукта.

* **Ключевой принцип** Middle: вы выбираете стратегию и объясняете её. Вы отвечаете за то, чтобы команда работала с Git единообразно.

Курсы и книги (Middle)

[Git branching strategies for documentation projects (Redocly)](https://redocly.com/blog/git-branching-for-docs) - Разбор трёх стратегий ветвления специально для документации: trunk-based, GitHub flow, versioned branches. С диаграммами и рекомендациями;

[Git and GitHub for Mintlify](https://learn.mintlify.com/courses/git-github/overview) - Курс по Git для документационных команд: как работать с ветками, preview deployments, ревью, коллаборация с инженерами и PM-ами;

[Docs as Code (Home Office)](https://engineering.homeoffice.gov.uk/patterns/docs-as-code/) - Государственный стандарт Великобритании: как выстроить docs-as-code в команде, какие инструменты использовать, как интегрировать писателей в dev-команды;

[Git Workflows (gitworkflows(7), man page)](https://git-scm.com/docs/gitworkflows) - Официальное описание рабочих процессов Git: как разбивать изменения на логические шаги, как работать с поддерживаемыми ветками;

[«Pro Git» (главы 4–7)](https://git-scm.com/book/en/v2) - Главы о ветвлении, rebase, worktree, настройке Git-сервера — для Middle-уровня.
