## Middle: «Настраиваю и автоматизирую»

На Middle-уровне редактор перестаёт быть «просто местом, где я пишу». Теперь это конфигурируемая среда, которую вы настраиваете под проект и команду. Вы отвечаете за то, чтобы редактор помогал соблюдать стандарты: линтинг, форматирование, проверка ссылок — всё это работает автоматически.

Что входит в Middle-уровень:

* **Workspace-конфигурация:** создание .vscode/settings.json с настройками для проекта: editor.wordWrap, editor.rulers (направляющие на 80 и 120 символов), editor.formatOnSave, автоисправление markdownlint при сохранении.

* **Интеграция линтеров:** markdownlint (проверка синтаксиса), Vale (проверка стиля и терминологии). Настройка .vale.ini с правилами: запрет «utilize» вместо «use», единообразие терминов, проверка пассивного залога.

* **Prettier для Markdown:** настройка Prettier как форматтера по умолчанию, включение «format on save» для автоматического выравнивания списков, отступов и заголовков.

* **Сниппеты (User Snippets):** создание шаблонов для часто используемых блоков: командный блок с комментарием, admonition, таблица параметров.

* **Tasks:** настройка задач для запуска скриптов: проверка ссылок, сборка документации, валидация OpenAPI.

* **Git-интеграция:** использование встроенного Git-панели для ревью изменений, просмотр diff, создание коммитов из редактора.

*Ключевой принцип Middle: вы настраиваете редактор под проект и делитесь конфигурацией с командой. Workspace-настройки лежат в репозитории, чтобы каждый новый автор получал готовую среду.*

## Курсы и книги (Middle)

[Docs-as-Code Workshop: Полезные плагины для VS Code (GitHub)](https://github.com/itikineva/doc-as-a-code-workshop) - Список плагинов для docs-as-code: Markdown All in One, Draw.io Integration, OpenAPI (Swagger) Editor, PlantUML, Markdown Table. Репозиторий также содержит пример настройки Docusaurus и CI/CD для публикации документации;

[Vale Documentation (.vale.ini)](https://docs.vale.sh/topics/.vale.ini) - Официальная документация Vale: как настроить .vale.ini, как писать кастомные правила и как интегрировать проверку в VS Code. Страница объясняет структуру конфигурационного файла и управление правилами;

[Prettier Documentation](https://prettier.io/docs/en/) - Официальная документация Prettier: настройка для Markdown, интеграция с VS Code (через расширение esbenp.prettier-vscode) и конфигурация для обеспечения единообразного форматирования документов;

[«VSCode for Technical Writing» (m.php.cn)](https://m.php.cn/faq/1948549.html) - Статья на китайском, но с подробным разбором цепочки «написал → сохранил → проверилось»: Prettier как форматтер по умолчанию с включённым «format on save» + Vale (CLI + Vale Server) для проверки тона, терминологии и пассивного залога;

[VS Code Tasks Documentation](https://code.visualstudio.com/docs/editor/tasks) - Официальный гайд по Tasks: как запускать скрипты (проверка ссылок, сборка документации) из редактора через tasks.json, не переключаясь в терминал.
