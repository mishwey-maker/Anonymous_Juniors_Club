## Senior: «Определяю стандарт и масштабирую»

На Senior-уровне Markdown — это элемент архитектуры документации. Вы не просто выбираете диалект для команды, вы определяете, как Markdown вписывается в общую стратегию: как связаны рукописные гайды и генерируемый reference, как масштабируется документация на десятки тысяч файлов, как обеспечивается консистентность между командами и продуктами.

Что входит в Senior-уровень:

* **Архитектура разметки:** вы определяете, где использовать Markdown, а где — DITA, AsciiDoc или reStructuredText. Вы понимаете компромиссы: Markdown тривиален для контрибьюторов, но ограничен; AsciiDoc мощнее, но требует изучения; DITA — стандарт для структурированного авторства, но тяжёл.

* **Lightweight DITA (LwDITA):** вы знаете, как связать Markdown с структурированным авторством через LwDITA — открытый стандарт, который мостит разрыв между Markdown и DITA XML.

* **Governance и стандарты:** вы создаёте org-wide стайлгайд по Markdown, который используется несколькими командами. Вы определяете, как обрабатывать исключения, как проводить ревью, как обучать новых авторов.

* **Инструментальная стратегия:** вы выбираете SSG для организации, определяете пайплайн: Markdown → lint → build → deploy. Вы решаете, какие проверки обязательны, а какие — рекомендательны.

* **Автоматизация и масштабирование:** вы настраиваете автоматическую генерацию Markdown из источников истины (OpenAPI, docstrings), интеграцию с CI/CD, обработку тысяч файлов, поиск и метаданные.

* **Миграции:** вы руководите миграцией с одного диалекта/SSG/платформы на другой, сохраняя контент, ссылки и историю.

*Ключевой принцип Senior: вы определяете правила игры и отвечаете за их соблюдение в масштабе. PM-ы и инженеры приходят к вам за советом по документации до начала работы над фичей.*

## Курсы и книги (Senior)

[Implementing Structured Authoring Practices in a Docs-as-Code Framework (ACM)](https://dl.acm.org/doi/10.1145/3641237.3691677) - реальный кейс миграции с DITA на Markdown в IBM Cloud: компромиссы, уроки, практики выбора инструментов

[Technical Documentation Standards for BMAD](https://cdn.jsdelivr.net/npm/cc4pm@2.0.6/_bmad/_memory/tech-writer-sidecar/documentation-standards.md) - пример строгого внутреннего стандарта: CommonMark, стайлгайд, правила compliance, Mermaid

[DITA and Lightweight DITA (LwDITA)](https://www.oasis-open.org/committees/download.php/61809/LwDITA-v1.0-cn01-1.pdf) - Официальное введение в LwDITA: как связать Markdown со структурированным авторством, маппинг XML/HTML5/Markdown

[Docs for Developers (Jared Bhatti et al.)](https://link.springer.com/book/10.1007/979-8-8688-2509-5) - не про Markdown напрямую, но про то, как строить документацию в масштабе: архитектура, процессы, метрики, работа с инженерами

[Write the Docs: Software Documentation Guide](https://www.writethedocs.org/guide/) - лучшие практики для документации в целом, включая выбор разметки и инструментов

[Awesome Technical Writing Learning (GitHub)](https://github.com/wongyah/awesome-technical-writing-learning) - кураторский список бесплатных ресурсов по техническому писательству, включая стайлгайды и инструменты
