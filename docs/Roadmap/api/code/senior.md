## Senior: «Определяю стандарт и управляю lifecycle примеров»

На Senior-уровне примеры кода становятся **элементом архитектуры документации**. Вы не просто создаёте примеры, вы **управляете их lifecycle**: стандартизация, автоматизация, масштабирование, обучение команд.

**Что входит в Senior-уровень:**

- **Стратегия примеров:** вы определяете, какие типы примеров обязательны для каждого продукта, как они связаны с другими типами документации (tutorial, how-to, reference), как обеспечивается консистентность между командами.
- **Governance:** вы определяете политику: кто отвечает за актуальность примеров, как проверяется их работоспособность, как обрабатываются breaking changes.
- **Масштабирование:** вы проектируете систему, которая выдерживает рост: добавление новых API, языков, версий без ручной работы.
- **CI/CD для примеров:** вы настраиваете пайплайн: синтаксическая проверка → тестирование против контролируемой среды → публикация. Вы используете CI-гейты для проверки свежести примеров.
- **Стандарты примеров:** вы определяете, как оформлять примеры: форматирование, комментарии, обработка ошибок, безопасность.
- **Обучение:** вы обучаете команды написанию примеров, проводите воркшопы, создаёте внутренние стандарты.
- **Метрики:** вы измеряете эффективность примеров: time-to-first-call, support tickets, adoption.

*Ключевой принцип Senior: вы **определяете правила игры** и **отвечаете за их соблюдение в масштабе**. Примеры кода становятся частью процесса разработки, а не разовым действием.*

### Курсы и книги (Senior)

[Docs for Developers (Jared Bhatti et al.)](https://link.springer.com/book/10.1007/978-1-4842-7295-1) - Стратегия документации, архитектура, масштабирование, обучение команды, включая code samples;

[API7.ai: Incorporating Code Samples (продвинутые разделы)](https://api7.ai/blog/code-samples-in-api-documentation) - Управление портфелем примеров, метрики, масштабирование;

[Google Developer Documentation Style Guide — API reference code comments](https://developers.google.com/style/api-reference-comments) - Стандарты для API reference: code samples на каждой странице (5–20 строк), ссылки на reference;

[GitBook: Adding custom code samples](https://docs.gitbook.com/content-editor/blocks/code-block) - Как добавлять кастомные примеры через `x-codeSamples`, интеграция с Fern-generated SDK;

[Mintlify: Add SDK examples](https://mintlify.com/docs/api-playground/sdk-examples) - Автоматическая генерация примеров через Speakeasy, добавление в OpenAPI.
