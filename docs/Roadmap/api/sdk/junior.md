На Junior-уровне SDK-документация — это **пошаговое руководство для разработчика**, который впервые сталкивается с вашей библиотекой. Вы учитесь писать quickstart, документировать установку и описывать базовые операции по готовому шаблону. Ключевой сдвиг: вы перестаёте «пересказывать» сигнатуры методов и начинаете **вести разработчика от нуля до первого работающего вызова**.

**Что входит в Junior-уровень:**

- **Понимание SDK vs API:** API — это контракт на уровне HTTP. SDK — это **клиентская библиотека**, которая оборачивает API в удобный для конкретного языка интерфейс. Документация SDK отвечает на вопрос «Как использовать библиотеку в моём проекте?».
- **Структура quickstart:** Prerequisites (что нужно до начала) → Installation (команда пакетного менеджера) → Authentication (как передать credentials) → First call (минимальный работающий пример) → Next steps (куда идти дальше).
- **Установка:** вы документируете команды для разных пакетных менеджеров (npm, pip, Maven, Gradle), указываете минимальную версию языка и зависимости.
- **Аутентификация:** вы показываете, как создать клиент и передать credentials. Пример должен быть самодостаточным: разработчик копирует его, подставляет свой токен и запускает.
- **Базовые операции:** вы документируете CRUD-операции (create, read, update, delete) с минимальными примерами. Каждый пример показывает happy path.
- **Inline-комментарии:** вы добавляете комментарии в код, объясняющие неочевидные параметры и возвращаемые значения.
- **Проверка работоспособности:** вы тестируете каждый пример в реальном проекте, убеждаясь, что он компилируется и выполняется.

*Ключевой принцип Junior: вы **ведёте разработчика** от установки до первого успешного вызова. Если пример не работает — это ваша ошибка, а не проблема читателя.*

### Курсы и книги (Junior)

[Creating Effective Documentation for Developers (LFC112) (Linux Foundation)](https://training.linuxfoundation.org/training/creating-effective-documentation-for-developers-lfc112/) - Курс для технических писателей с базовыми знаниями программирования: типы документации, API-элементы, code-based reference, планирование документации в разработке;

[SDK documentation — Archbee Blog](https://www.archbee.com/blog/sdk-documentation) - Введение в разницу между SDK и API, что должна включать SDK-документация, примеры из реальных SDK;

[Google Technical Writing One](https://developers.google.com/tech-writing/one) - База: аудитория, структура, ясность. Применимо к quickstart и примерам кода;

[Write the Docs: Software Documentation Guide](https://www.writethedocs.org/guide/) - Best practices для документации, включая quickstart и code samples;

[Diátaxis Framework — Tutorials](https://diataxis.fr/tutorials/) - Понимание разницы между tutorial (обучение) и how-to (решение задачи). SDK quickstart — это tutorial.
