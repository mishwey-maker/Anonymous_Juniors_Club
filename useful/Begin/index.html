    Начальная настройка

    1. Установить python и git

    Скачайте дистрибутивы с официальных сайтов и установите их на компьютере: python (https://www.python.org/downloads/); git (https://git-scm.com/download/win)

    1. Зарегистрировать аккаунт в github

    Сделать это можно на github.com (https://github.com/) (регистрация по кнопке Sign up в правом верхнем углу).

    1. Для работы нам понадобится какой-нибудь текстовый редактор. Я настоятельно рекомендую использовать Visual Studio Code (https://code.visualstudio.com/) — это классический редактор кода с расширенными функциями, который удобно использовать для работы с облегченными языками разметки.

    Настройка окружения

    1. Проверить версионность python и git:

    python --version

    git --version

    Если всё сделано верно, комадная строка вернёт вам версии установленного по:

    C:\Users\User1>python --version
Python 3.10.2

C:\Users\User1>git --version
git version 2.33.0.windows.2

    Создать репозиторий Git

    1. Войдите в свой аккаунт GitHub;
    2. В правом верхнем углу нажмите кнопку [+] и выберите пункт «New repository»;

    3. Заполните поля в открывшейся форме:

      ✒️ Repository name — обязательное поле, название и slug вашего репозитория. Вы можете использовать латиницу, цифры и некоторые символы (точку, дефис и нижнее подчёркивание). Постарайтесь придумать название, которое будет отражать суть вашего репозитория. Мой, например, называется parawriter_docs;

      ✒️ Description — описание репозитория. Это поле необязательное, заполните его по своему усмотрению. Я ленивый, поэтому оставил описание пустым);

      ✒️ Public or Private – Публичный репозиторий будет виден всем пользователям Интернета (в режиме просмотра), а в приватном вы сами настраиваете список допущенных лиц. В рамках курса я рекомендую создать публичный репозиторий. Для этого выберите опцию Public;

      ✒️ Add a README file. Readme — это файл с описанием проекта. Я предлагаю добавить readme, потом мы зафиксируем в нём особенности работы с проектом. Активируйте этот чекбокс;

      ✒️ Add .gitignore. В файле .gitignore содержится список неотслеживаемых гитом файлов и папок. Нам это пока не нужно, оставьте чекбокс неактивным;

      ✒️ Choose a license. Лицензии защищают наше авторское право на создаваемый в репозитории продукт. В рамках этого курса я предлагаю установить стандартную универсальную общественную лицензию, которая разрешает всем желающим пользоваться вашими наработками. Раскройте список и выберите GNU General Public License;

    4. Нажмите кнопку Create repository.

    Настройка директории

    1. Определить в какой папке на компьютере будет размещаться проект.

    Теперь нужно перейти на нее в приложении командной строки. Для этого открыть CMD и выполнить команду: 

    cd <Путь к папке> 

Например:

cd C:\Users\User1\parawriter

    1. Клонировать git-репозиторий в эту папку с помощью команды git clone.

    2. Войти в свой аккаунт на GitHub и открыть репозиторий.

    3. Нажать кнопку <> Code.

    4. В выпадающем окне на вкладке Local в разделе Clone выберите HTTPS и скопировать web url репозитория.

    5. Перейти в CMD и выполнить команду: 

        git clone repository-url
      Система сообщит, когда репозиторий будет полностью клонирован: 
      C:\Users\User1\parawriter>git clone https://github.com/novillero/parawriter_docs.git
Cloning into 'parawriter_docs'...
remote: Enumerating objects: 4, done.
remote: Counting objects: 100% (4/4), done.
remote: Compressing objects: 100% (3/3), done.
remote: Total 4 (delta 0), reused 0 (delta 0), pack-reused 0 (from 0)
Receiving objects: 100% (4/4), 7.56 KiB | 7.56 MiB/s, done.
C:\Users\User1\parawriter>

    6. В папке появилась новая папка с репозиторием. Чтобы работать с проектом, нужно перейти в эту папку. Для этого необходимо выполнить команду cd: 

      C:\Users\User1\parawriter>cd C:\Users\User1\parawriter\parawriter_docs
C:\Users\User1\parawriter\parawriter_docs>

    7. Проверить состояние проекта - выполнить команду git status 
      C:\Users\User1\parawriter\parawriter_docs>git status
On branch main
Your branch is up to date with 'origin/main'.

nothing to commit, working tree clean

C:\Users\User1\parawriter\parawriter_docs>

      Система сообщает нам, что мы находимся в основной ветке проекта main, а также что наша локальная версия ветки main обновлена и совпадает с оригинальной main. Сообщение nothing to commit, working tree clean говорит о том, что мы еще не внесли никаких изменений, которые можно было бы зафиксировать.

    Первый файл

    1. Открыть CMD и перейти в папку проекта с помощью команды cd путь_к_папке;

    2. Проверить состояние проекта, выполнив команду git status

      Что нужно смотреть в статусе репозитория? То, что вы находитесь в нужной ветке (main) и что у вас нет незафиксированных изменений;

    3. Обновить репозиторий, выполнив команду git pull.

      Эта команда забирает актуальную версию ветки из оригинального репозитория на наш компьютер. Сейчас таких изменений нет, но мы будем следовать правилам;

    4. Каждая новая задача (а перед нами стоит задача добавить первый файл) должна выполняться в отдельной ветке. Создать новую ветку task-1-add-file, отколов её от ветки main. Для этого выполнить команду git branch task-1-add-file

    5. Новая ветка создана, но git status покажет, что вы до сих пор находится в ветке main. Чтобы переключиться на рабочую ветку, выполнить команду git switch task-1-add-file;

    6. В папке проекта создать файл index.md.

    7. После создания нового файла нам нужно отправить его на сервер:

    8. Вернуться в CMD и снова выполните команду git status. Система показывает, что в проекте есть изменения: 

      C:\Users\User1\parawriter\parawriter_docs>git status
On branch task-1-add-file
Untracked files:
  (use "git add <file>..." to include in what will be committed)
        index.md

nothing added to commit but untracked files present (use "git add" to track)

    9. Перед тем, как создать коммит, нужно сообщить гиту, какие изменения требуется зафиксировать в коммите. Для этого используется команда git add. Так как мы собираемся зафиксировать все изменения, выполнить команду в таком виде: git add .;

    10. Теперь файл index.md проиндексирован. Для создания коммита выполнить команду git commit -m "краткое описание изменений":

    C:\Users\User1\parawriter\parawriter_docs>git commit -m "Добавил новый файл index.md"
[task-1-add-file df62424] Добавил новый файл index.md
 1 file changed, 0 insertions(+), 0 deletions(-)
 create mode 100644 index.md

    Система сообщает о том, что изменения зафиксированы.

    Отправить коммит на сервер, выполнив команду git push. Так как вашей рабочей ветки ещё нет на сервере, используйте команду с флагом set-upstream: git push --set-upstream origin task-1-add-file. Это нужно только для первого обновления, все последующие обновления ветки можно будет проводить командой git push без флага;

    файл index.md отправился на сервер. Нам осталось создать пул-реквест и слить рабочую ветку и ветку main, чтобы обновить проект.

    Первый пул-реквест

    1. Открыть репозиторий в GitHub. Теперь, если вы раскроете список веток (кнопка слева над файлами репозитория, на кнопке отображается название текущей ветки main), увидите рабочую ветку task-1-add-file. Переключится на неё: в списке файлов появился новый файл index.md. Это значит, что изменения успешно добрались до сервера.

    Чтобы провести ревью, а потом влить внесённые изменения в проект, нужно создать запрос на слияние веток: Pull request.

    1. В верхнем меню выбрать пункт Pull requests. Страничка пока пустая, потому что не создано ни одного запроса;

    2. Нажать зелёную кнопку New pull request;

    3. В разделе «Compare changes» выбрать ветки:

    В поле base добавить ветку main, а в поле compare — ветку task-1-add-file.

    Гитхаб проводит проверку возможности слияния и выносит вердикт: Able to merge. Значит, всё хорошо, конфликтов не обнаружено, можно создавать пул-реквест.

    1. Нажать кнопку Create pull request;

    2. Придумайте название и описание пул-реквеста: заполните поля Add a title и Add a description. Обычно в компаниях разработаны правила наименования пул-реквестов, но мы с вами не в обычной компании) Поэтому предлагаю придерживаться простой рекомендации: название должно кратко отражать суть задачи, а описание — подробности вносимых изменений.

    Я назову пул-реквест «Добавление первого файла», а в описании расскажу, что именно я сделал: «Создал и добавил новый файл index.md».

    1. Ещё раз нажать кнопку Create pull request. Поздравляю, запрос создан!

    Этот запрос нужен не только для того, чтобы слить ветки. Именно здесь может проходить процесс проверки задачи и внесение правок. Обычно ссылка на пул-реквест прикрепляется к задаче, и назначенный ревьюер приходит и проверяет вашу работу. Он может перейти на вкладку Files changed и посмотреть файлы, которые вы изменили, а также оставить комментарии к любой строке этих файлов. Эти комментарии будут отображаться на главной странице пул-реквеста, вы можете отвечать на них, ну, и конечно, вносить изменения по требованию ревьюера. После того, как все проверки будут пройдены, а правки согласованы, пул-реквест принимается и ваша рабочая ветка вливается в main, то есть добавляется в основной проект.

    1. Внести изменения в файл index.md и отправьте эти изменения на сервер.

    Подсказка

    Всю работу над задачей мы проводим в одной ветке. Если в процессе ревью вы получили правки, то вносить их нужно в той же рабочей ветке, а потом по уже знакомому пути отправить изменения на сервер (проиндексировать изменения → создать коммит → отправить коммит). Если всё сделано правильно, ваш новый коммит попадёт в уже созданный пул-реквест.

    Ожидаемый результат

    Файл index.md изменён, в пул-реквесте на вкладке Commits отображаются два коммита.

    Слияние

    Задача провести слияние и влить рабочую ветку task-1-add-file в главную ветку main.

    1. Открыть пул-реквест в GitHub и промотать вкладку Conversation до блока с подтверждением запроса;
    2. Нажать кнопку Merge pull request.
    3. Нажать кнопку Confirm merge;
    4. GitHub автоматически вольёт изменения в ветку main и сообщит о том, что всё прошло успешно: «Pull request successfully merged and closed».

    Установка MkDocs

    1. Установить генератор MkDocs. Для этого откройте CMD и выполните команду:
    pip install mkdocs
    1. Установить тему MkDocs material theme с помощью команды:
    pip install mkdocs-material

    1. Перейти в папку с репозиторием проекта с помощью команды cd путь_к_папке;

    2. Проверить состояние проекта с помощью команды git status. Убедится, что находитесь в главной ветке. Если нет, переключитесь на неё (команда git switch main);

    3. Обновить репозиторий с помощью команды git pull;

    4. Отколоть новую ветку, в которой будет совершаться настройка проекта. Например task-2-setup-mkdocs;

    5. Открыть папку проекта через проводник;
    6. В папке создать mkdocs.yml. Это конфиг, с помощью которого будет происходить настройка документации;
    7. Привести структуру проекта к шаблону:
    ├─ docs/
│  └─ index.md
└─ mkdocs.yml

    По шаблону все исходники должны лежать в подпапке docs. Создать папку docs и перенести туда файл index.md; 10. Открыть файл mkdocs.yml (с помощью VS Code или любого другого редактора кода) и добавить название проекта: site_name: [Название сайта] 11. Сохранить изменения в mkdocs.yml и закрыть файл.

    1. Выполнить команду mkdocs serve Если всё сделано правильно, в ответ придёт адрес локального порта, на котором собралась дока: 
      C:\Users\User1\parawriter\parawriter_docs>mkdocs serve
INFO    -  Building documentation...
INFO    -  Cleaning site directory
INFO    -  Documentation built in 0.11 seconds
INFO    -  [11:59:50] Watching paths for changes: 'docs', 'mkdocs.yml'
INFO    -  [11:59:50] Serving on http://127.0.0.1:8000/
      Если перейти по адресу в последней строке, то можно увидеть как будет выглядеть сайт.

    Теперь дело за малым: закоммитьте изменения, отправьте их на сервер, создайте пул-реквест и влейте рабочую ветку в ветку main.

    1. Выполнить команду -git add .

    2. Выполнить команду git commit -m "краткое описание изменений".

    3. В GitHub выберите пункт Pull requests.

    4. Нажать кнопку New pull request.
    5. В разделе «Compare changes» выбрать ветки: В поле base нужно добавить ветку main, а в поле compare — ветку с которой ведётся работа.
    6. Нажать кнопку Create pull request.
    7. Заполнить описание пул-реквеста.
    8. Нажать кнопку Create pull request.

    Настройка структуры сайта

    Пример структуры сайта:

    Главная страница  // файл index.md
├─ Онбординг тех.писателя // файл onboarding.md
│  ├── Первый урок // файл onboarding/lesson_1.md
│  ├── Второй урок // файл onboarding/lesson_2.md
│  ├── <...>
│  └── Последний урок // файл onboarding/lesson_last.md
└─ Docs-as-code для самых маленьких // файл docs_as_code.md
   ├── Первый урок // файл docs_as_code/lesson_1.md
   ├── Второй урок // файл docs_as_code/lesson_2.md
   ├── <...>
   └── Последний урок // файл docs_as_code/lesson_last.md
   ```

   >!Все изменения делать в новой ветке.

Пример заполнения mkdocs.yml

```shell
site_name: Rivers and lakes # Название сайта
site_description: Rivers and lakes of Russia # Описание сайта, добавляется в meta-теги
theme: # Тема сайта, информация о ее параметрах
  name: material # Название темы
  logo: logo.svg # Ссылка на логотип сайта
  font:
    text: Roboto # Шрифт текста
    code: Roboto Mono # Шрифт для текста кода
  features:
    #- navigation.sections
    - navigation.path # Хлебные крошки
    - navigation.indexes # Позволяет создавать корневые страницы разделов меню. Корневая страница должна лежать в папке раздела и называться index.md. Пример использования корневых страниц приведен ниже в настройках nav
    #- navigation.tabs # Верхнее меню
    #- navigation.tabs.sticky # Фиксация верхнего меню
    #- Navigation sections # Настройка спойлеров в левом меню
    #- navigation.expand # Разворачивает спойлеры в левом меню по умолчанию
    #- toc.integrate # Фиксирует оглавление страницы в левом меню
    - navigation.instant # Функция быстрой загрузки страниц
    - navigation.top # Добавляет кнопку «к началу» для быстрой обратной прокрутки страницы
    - search.suggest # Подсказки при вводе поискового запроса
    - search.highlight # Подсветка результатов поиска в тексте страницы
    - content.code.copy # Кнопка копирования в блоке кода

  language: ru # Язык
  palette: # Настройки светлой и тёмной тем
    # Настройки светлой темы
    - scheme: default 
      toggle:
        icon: material/weather-sunny # Иконка для активации светлой темы
        name: Выключить солнышко # Всплывающий текст-подсказка
      primary: blue # Основной цвет
      accent: purple # Акцентный цвет
    # Настройки тёмной темы
    - scheme: slate
      toggle:
        icon: material/weather-night
        name: Позвать солнышко
      primary: deep purple
      accent: blue

nav: # Структура сайта

    Настройка CI

    1. Открыть CMD и перейти в папку проекта с помощью команды cd;
    2. Создать новую рабочую ветку;
    3. Открыть папку с проектом через проводник;
    4. Создать новую папку .githubв корне проекта;
    5. Внутри папки .github создать папку workflows;
    6. Внутри папки workflows создайте новый файл ci.yml;
    7. Открыть файл ci.yml с помощью VS Code или другого редактора;
    8. Скопировать текст ниже и вставить его в файл ci.yml:

    name: ci
on:
  push:
    branches:
      - main
permissions:
  contents: write
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-python@v4
        with:
          python-version: 3.x
      - uses: actions/cache@v2
        with:
          key: ${{ github.ref }}
          path: .cache
      - run: pip install mkdocs-material
      - run: mkdocs gh-deploy --force
    9. Сохранить изменения, отправить их на сервер;

    1. Войти в GitHub, создать пул-реквест и слить рабочую ветку с веткой main.

    2. Перейти в раздел Actions → All workflow. В списке workflow появилась новая запись — это и есть наш новый автоматический процесс. Если он завершился успешно (все этапы отмечены зелёными галочками), значит, всё получилось. Для проверки можете внести какие-нибудь изменения в исходные файлы и добавить их в ветку main. После сливания рабочей ветки с веткой main в Actions опять должен запуститься новый workflow. Дождитесь его завершения, перейдите на сайт и убедитесь, что там отобразились ваши изменения.
